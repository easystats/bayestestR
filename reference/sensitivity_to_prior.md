# Sensitivity to Prior

Computes the sensitivity to priors specification. This represents the
proportion of change in some indices when the model is fitted with an
antagonistic prior (a prior of same shape located on the opposite of the
effect).

## Usage

``` r
sensitivity_to_prior(model, ...)

# S3 method for class 'stanreg'
sensitivity_to_prior(model, index = "Median", magnitude = 10, ...)

# S3 method for class 'brmsfit'
sensitivity_to_prior(model, index = "Median", magnitude = 10, ...)
```

## Arguments

- model:

  A Bayesian model (`stanreg` or `brmsfit`).

- ...:

  Arguments passed to or from other methods.

- index:

  The indices from which to compute the sensitivity. Can be one or
  multiple names of the columns returned by `describe_posterior`. The
  case is important here (e.g., write 'Median' instead of 'median').

- magnitude:

  This represent the magnitude by which to shift the antagonistic prior
  (to test the sensitivity). For instance, a magnitude of 10 (default)
  means that the mode will be updated with a prior located at 10
  standard deviations from zero, on the opposite side of the effect.

## Value

A data frame with a `Parameter` column and one `Sensitivity_*` column
for `Median` and for each other index.

## Details

For `brmsfit` models, all slopes must have a normal, student_t, or
cauchy prior, because only these priors are supported for moving to an
antagonistic location. The default flat priors of **brms** are not
supported, so set the priors with
[`brms::set_prior()`](https://paulbuerkner.com/brms/reference/set_prior.html)
when fitting the model. Multivariate models are not supported. Only
regular slopes of the main formula get a new prior. Other parameters,
such as non-linear parameters or monotonic effects, give an error, and
so do bounded slope priors. Intercepts, including the thresholds of
ordinal models, are not changed.
